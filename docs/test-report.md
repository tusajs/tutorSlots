## 2. Стратегия

| Уровень | Что проверяем | Как |
|---|---|---|
| Модульный | Классификация цвета, разбор файла, сдвиг пояса, интервалы, статистика, формат отчёта | Google Test и JUnit; один и тот же набор сценариев в обеих реализациях |
| Интеграционный | Ответ Google Sheets → TSV → отчёт; кэш и чтение с диска; хранилище пользователей; HTTP-запросы к Telegram | JUnit с фикстурой ответа API (`sheets-response.json`), временными файлами и локальным HTTP-сервером вместо Telegram |
| Логика бота | Сценарии диалога: выбор пояса, ввод своего пояса, `/stats`, недоступность Google | JUnit с фейковым `BotApi`, который записывает всё отправленное |
| Эквивалентность реализаций | C++ и Kotlin выдают одинаковый результат | Побайтное сравнение отчётов на всех допустимых смещениях |
| Системный (ручной) | Работа с настоящей таблицей и настоящим Telegram | Чек-лист, раздел 5 |

Тесты, которым нужны настоящие ключи Google и Telegram, в автоматический набор не входят: результат не должен зависеть от сети и секретов. Эти сценарии проверены вручную.

## 4. Классы эквивалентности и граничные значения

| Вход | Корректные классы | Некорректные классы | Граничные значения в тестах |
|---|---|---|---|
| Цвет ячейки | зелёный (в т. ч. бледный), красный (в т. ч. бледный), белый, нет заливки | не `#RRGGBB`, лишние/недостающие символы | `#F0F0F0` — белый (порог 240), `#EFEFEF` — серый; `#000000`; магента, синий, жёлтый — «другой» |
| Текст ячейки | пусто, имя | — | только пробелы и табуляции = пусто; табуляция и перевод строки внутри ячейки Google |
| Время | `9:00`, `09:00`, `9:00:00` (из Google) | `24:00`, `9:5`, `25:00`, текст | `0:00`, `23:00` |
| День | `MON`…`SUN` в любом регистре; русские названия в заголовке таблицы | `XYZ` | — |
| Строка файла | 2–4 поля, CRLF, BOM | 1 поле, 5 полей | строка без концевых табуляций |
| Смещение клиента | −12:00 … +14:00 с шагом 15 мин; `+7`, `UTC+3`, `GMT-4` | `+15`, `-13`, `+5:20`, `7` (без знака), текст | −12:00, +14:00, +5:30, +5:45 |
| Ввод пояса в боте | город, смещение, IANA-имя | `марс`, `Mars/Olympus` | летнее/зимнее время (Берлин), Москва без перехода |
| Порог раннего начала | `00:00` (выкл.), `08:00`, `09:30` | `25:00`, `8`, `утро` | слот ровно в 08:00 (показан), в 07:45 (скрыт) |
| Сдвиг недели | — | — | вс 23:00 → пн; пн 01:00 → вс; слот, пересекающий полночь клиента в поясе +5:30 |

## 6. Найденные дефекты

| ID | Где | Описание | Как найден | Исправление | Статус |
|---|---|---|---|---|---|
| D-01 | `core-cpp`, `CellClassifier::classifyColor` | Бледно-зелёный `#B7E1CD` (стандартный цвет палитры Google Таблиц) считался «другим», то есть занятым. Правило «зелёный канал больше остальных минимум на 40» не учитывало, что в пастельных цветах много синего: `g − max(r, b) = 225 − 205 = 20`. | Unit-тест `AC07_PaleGreenIsGreen` | Классификация по HSV: насыщенность ≥ 15 %, оттенок 75°…165° — зелёный, 340°…20° — красный. Добавлен тест `ColorEdgeCases` на границы. | Исправлен |
| D-02 | `core-cpp`, `ReportWriter::formatTime` | GCC с `-Wformat-truncation` предупреждал о возможной обрезке строки в `snprintf` в буфер на 8 байт. При некорректном (отрицательном или огромном) числе минут вывод был бы обрезан. | Сборка с `-Wall -Wextra -Werror` | Форматирование через `std::to_string`, без буфера фиксированного размера | Исправлен |
| D-03 | `app-kotlin`, вывод в консоль | Сообщения на русском в консоли и логах выводились как `?????`. Java 17 на Windows пишет в stdout в кодировке системы (cp1251), а консоль работает в cp866 — кириллица искажается. | Ручной запуск `bot` без настроек | Консольные и лог-сообщения переведены на английский (как в C++ CLI). По-русски — только сообщения в Telegram (всегда UTF-8) и картинка. | Исправлен |
| D-04 | `app-kotlin`, сеть | Бот не мог подключиться к `api.telegram.org`: `HTTP connect timed out`. Причины две: Telegram API недоступен у провайдера напрямую, а Java по умолчанию **игнорирует системный прокси Windows**, так что VPN-клиент в режиме «системный прокси» не помог бы. При включённом VPN мешало раздельное туннелирование, которое не пускало Telegram через VPN. | Ручной тест M-04 | В `Main.kt` включено `java.net.useSystemProxies=true`; добавлена настройка `PROXY=host:port`; в README описана настройка раздельного туннелирования (`api.telegram.org` и подсети Telegram) | Исправлен |

### Наблюдения (не дефекты)
- При ручной проверке опечатка в тексте ячейки не повлияла на статус. Любой непустой текст означает занятый слот.
- Gradle показывает `83% EXECUTING`, пока бот работает. Это особенность задачи `run`, а не зависание.
