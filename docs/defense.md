# Защита TutorSlots

Доклад рассчитан примерно на 8 минут с показом команд и GitHub. Для защиты достаточно jdk 17 и обезличенного снимка из репозитория. Для онлайн-демо понадобится настроенный бот.

## 0:00–0:45 · Задача

TutorSlots показывает свободные часы репетитора в часовом поясе клиента. Репетитор по-прежнему ведёт Google Таблицу в московском времени. Клиент в Telegram выбирает город или пояс, отправляет команду /slots и получает картинку. Один и тот же час записан в таблице один раз, хотя клиенты видят его по-разному.

Ключевое правило можно показать на двух ячейках. Пустая зелёная ячейка свободна. Если в зелёной ячейке есть текст, слот занят. Так вписанное занятие имеет приоритет над цветом. Бот показывает окна и, если задан контакт, объясняет, кому написать для записи.

## 0:45–1:35 · Структура проекта

В репозитории два модуля. В core-cpp заголовок `include/tutor_slots/core.hpp` объявляет типы и функции, `src/core.cpp` реализует расчёт, а `src/main.cpp` принимает аргументы и выводит отчёт. CMake собирает библиотеку ядра, консольную программу и Google Test.

В app-kotlin точка входа находится в Main.kt. Пакет presentation обрабатывает команды и рисует фото, data получает и хранит расписание, domain связывает эти операции, а core содержит порт алгоритма на Kotlin. Программы обмениваются данными одного формата. Для сопоставления запускаем обе на одном TSV и сравниваем текстовые отчёты.

## 1:35–2:50 · Как работает команда /slots

Получив команду, TutorBot читает пояс клиента из UserSettingsStore. Если выбора нет, сначала появляются кнопки. Если пояс сохранён, SlotsService запрашивает таблицу у ScheduleRepository. Репозиторий использует свежий снимок в течение пяти минут, а затем пробует обновить его. Если обновление завершается ошибкой, он ищет последний снимок в памяти или на диске. Бот показывает предупреждение и дату снимка.

SheetsClient получает от Google текст и заливку. SheetsParser превращает ячейки в TSV. SnapshotReader читает строки, классифицирует слоты и записывает предупреждения по некорректным данным. SlotsService передаёт свободные слоты в IntervalBuilder, получает план и отправляет его рендереру. Java2D рисует PNG, который TelegramBotApi передаёт в исходный чат.

## 2:50–3:50 · Фрагмент алгоритма

Откройте `app-kotlin/src/main/kotlin/tutorslots/core/Core.kt` и найдите `object IntervalBuilder`. Цикл `for (slot in slots)` перебирает слоты. Условие со словом `continue` пропускает занятые. Затем `TimeShift.toClient` переносит начало в пояс клиента. Для Москвы это UTC+3, для Новосибирска UTC+7. Значит, 12:00 становится 16:00.

Два соседних часовых слота 16:00–17:00 и 17:00–18:00 дают один интервал 16:00–18:00. Проверка сравнивает начало следующего интервала с концом предыдущего. Если начало не позже конца, два интервала объединяются. Москва 01:00 в понедельник для UTC — это воскресенье 22:00. Расчёт использует циклическую неделю из 10 080 минут, чтобы обработать такой переход.

## 3:50–5:50 · Демонстрация

Заранее выполните сборку из корня проекта. Под Windows используется PowerShell.

```powershell
Push-Location app-kotlin
.\gradlew.bat fatJar
Pop-Location
$jar = 'app-kotlin\build\libs\tutor-slots-1.0-all.jar'
java -jar $jar render samples/snapshot.tsv --zone Europe/Moscow --out moscow.png
java -jar $jar render samples/snapshot.tsv --zone Asia/Novosibirsk --out novosibirsk.png
```

На защите откройте обе картинки и сравните первое понедельничное окно. В Москве это 09:00–11:00, в Новосибирске 13:00–15:00. В обеих картинках порог равен 08:00 местного времени, поэтому после пересчёта часть ночных окон пропадает. Этот режим использует тот же Kotlin-рендерер, что и бот, и работает по локальному TSV.

Если бот был настроен заранее, отправьте /tz, выберите Новосибирск, затем отправьте /slots. Покажите подпись с поясом. Для демонстрации статистики понадобится ID репетитора в настройках. При отсутствии подключения продолжайте с двумя локальными PNG.

## 5:50–6:55 · Проверки

В C++ используется Google Test, в Kotlin — JUnit. В качестве примера покажите тест `AC13_MergesConsecutiveSlots` или его Kotlin-версию `ac13_mergesConsecutiveSlots`. На вход подаются соседние свободные часы, на выходе ожидается один интервал. Есть отдельные проверки перехода недели, дробного UTC-смещения и границы 08:00.

При сравнении версий обе программы запускаются на одном снимке. Workflow перебирает 105 смещений, от UTC−12:00 до UTC+14:00 с шагом 15 минут. Учитывается каждый байт отчёта. Это проверяет согласованность двух реализаций на контрольном входе. Проверки отдельных правил при этом остаются задачей тестов.

Пользовательский результат — свободное время в местном поясе. Для разработки важны общий формат TSV, проверяемое ядро и раздельные модули. По README можно повторить запуск и демонстрацию на локальном снимке.
