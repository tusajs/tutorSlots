# Сравнение реализаций ядра: C++ и Kotlin

Этап 4. Одна и та же логика (чтение снимка → статусы → сдвиг пояса → интервалы → статистика → отчёт) написана дважды: `core-cpp/src/core.cpp` и `app-kotlin/src/main/kotlin/tutorslots/core/Core.kt`.

## Проверка эквивалентности

| Проверка | Результат |
|---|---|
| Отчёт по `samples/snapshot.tsv` для всех 105 допустимых смещений (от UTC−12:00 до UTC+14:00 с шагом 15 минут) × 3 порога раннего начала (00:00, 08:00, 09:30) | 315 из 315 совпадают побайтно |
| Файл с ошибками (неизвестный день, дубль, неизвестный цвет, неверное время, бледно-зелёный) | stdout, предупреждения в stderr и код выхода совпадают |
| Общие эталоны `expected_utc+07.txt`, `expected_utc+05-30.txt` | Проверяются тестами обеих реализаций |
| Ответ Google Sheets API (`sheets-response.json`) → TSV → отчёт | Совпадает с эталоном (только Kotlin, в C++ нет сетевой части) |

Скрипт для повторной проверки на Windows: `scripts/compare.ps1`.

## Объём

| | C++ | Kotlin |
|---|---|---|
| Ядро, строк кода (без комментариев и пустых строк) | 276 (`core.hpp` + `core.cpp`) | 192 (`Core.kt`) |
| Консольная обёртка | 68 (`main.cpp`) | часть `Main.kt` (режим `report`) |
| Тесты ядра | 37 (Google Test) | 37 (JUnit 5) + 34 теста остального приложения |

Kotlin-версия примерно на 30 % короче: не нужен отдельный заголовочный файл, `data class` даёт готовые `equals`/`toString`, коллекции умеют `map`/`count`/`sortedBy`.

## Различия, которые пришлось учитывать

| Тема | C++ | Kotlin | Как сделали одинаково |
|---|---|---|---|
| Остаток от деления отрицательного числа | `-5 % 7 == -5` | `Math.floorMod(-5, 7) == 2` | В C++ двойной `mod`: `((x % n) + n) % n` |
| «Значения может не быть» | `std::optional<Rgb>` | `Rgb?` (nullable-тип) | Смысл один, но Kotlin проверяет null на этапе компиляции |
| Ошибки разбора строки | Возврат `nullopt` + `continue` | `?: run { …; return@forEachIndexed }` | Ни одна реализация не бросает исключений при разборе, всё идёт в `Diagnostic` |
| Строки и кодировка | Байты UTF-8; BOM — три байта `EF BB BF` | UTF-16; BOM — символ `﻿` | Тест `AcceptsShortLinesCrlfAndBom` в обеих версиях |
| «Пробельные» символы | `isspace`/свой `trim` — только ASCII | `trim()` по умолчанию убирает и Unicode-пробелы | В Kotlin свой `trimAscii()` с тем же набором символов, что и в C++ |
| Цифры | `isdigit` — только `0-9` | `isDigit()` принимает и арабские, и другие цифры Unicode | В Kotlin своя проверка `c in '0'..'9'` |
| Форматирование `09:05` | Первая версия на `snprintf` давала предупреждение `-Wformat-truncation` (дефект D-02) | `padStart(2, '0')` | В C++ переписано без буфера |
| Вещественная арифметика (оттенок HSV) | `double`, `std::fmod` | `Double`, оператор `%` | Обе следуют IEEE 754, поэтому результаты одинаковы. Пороги сравниваются с запасом |
| Сборка | CMake + MSVC/GCC, Google Test скачивается через `FetchContent` | Gradle + JVM 17, JUnit 5 из Maven Central | — |
| Время выполнения | Мгновенно (~1 мс) | ~0,3 с на запуск JVM, сама обработка ~5 мс | Для бота неважно: JVM запускается один раз |

## Выводы

- **C++** даёт маленький быстрый исполняемый файл без зависимостей, но много кода уходит на «ручную» работу: разбор строк, проверку символов, форматирование. Ошибки вроде отрицательного остатка или обрезки буфера ловятся только тестами и предупреждениями компилятора.
- **Kotlin** короче и безопаснее (null-safety, нет ручной памяти), а стандартная библиотека Java сразу даёт HTTP, JSON, часовые пояса с переходом на летнее время (`java.time`) и рисование картинок (Java2D). Поэтому вся работа с внешним миром — Google, Telegram, PNG — сделана на Kotlin.
- Самые неожиданные расхождения — не в алгоритме, а в мелочах: Unicode-пробелы, Unicode-цифры, BOM, знак остатка. Без побайтного сравнения отчётов их легко пропустить.
